Quick start 1At a glancePages 2-5 are enough to run the engine

What does it do?

  • Give it a sensitivity file (CRIF) for your derivatives and it calculates initial margin (IM) with the ISDA SIMM method, in USD.
  • It checks the input file strictly before calculating. If something is wrong, it does not calculate and tells you what is wrong and on which line.
  • It selects the SIMM version (2.5 to 2.8+2512) that applies to the valuation date.

Quick start 4Rules and troubleshootingThe most common mistakes

Six CRIF rules

1
Dates as 2026-06-30, equal to the valuation date you run with.
2
No thousands separators: 1000 (yes), 1,000 (no).
3
No spaces before or after a cell value.
4
Only AmountUSD is used. On USD rows Amount must equal AmountUSD.
5
Standard lower-case tenors only: 2w 1m 3m 6m 1y 2y 3y 5y 10y 15y 20y 30y (credit: 1y 2y 3y 5y 10y)
6
Some cells must be empty depending on the risk type. See the examples below and Reference, section 2.

2.4 Working in Excel

  • File type: save as "CSV UTF-8 (Comma delimited)". Other CSV types may garble non-ASCII text or fail to load.
  • Dates: open the saved file in Notepad and check that Excel did not turn 2026-06-30 into something like 6/30/2026. If dates were saved as numbers such as 46203, add --excel-serial-dates when running.
  • Numbers: 1000 and 1E+5 are fine; thousands separators are not.
  • Loading XLSX directly: one sheet only and no formulas (paste as values). Needs openpyxl.

2.5 Rows in currencies other than USD

  • AmountCurrency may be EUR and so on. AmountUSD must then hold the USD value converted by whoever produced the CRIF. The engine does not check FX rates; it only records a FX_RATE_UNVERIFIED warning.
  • If Amount and AmountUSD have different signs, or only one of them is zero, the row is rejected.

3. Writing the context file

The template is config\context.template.json; a filled-in example is examples\context.json.

FieldDescriptionExample
directioncollect (margin you receive) or post (margin you give). It does not change the amounts; it labels the result and selects the regulation column."collect"

netting_setDefault when a CRIF NettingSet value is blank"DEFAULT"
unit_declarationsFor each risk type, the unit your CRIF uses (unit) and the evidence for it (source)see below

Filling in unit_declarations

A wrong sensitivity unit (for example per 1% instead of per 1bp) can make the result 100 times too large or too small. So for each risk type you record the evidence that your CRIF was produced in that unit.

"Risk_IRCurve": { "unit": "PV01_PER_1BP", "source": "Risk system CRIF specification v3.2, section 4.1" }
  • unit: keep the template value. Changing it causes a UNIT_MISMATCH error.
  • source: the document or check that confirms the unit. If it is empty for a risk type in your CRIF, the run is blocked. Risk types you do not use may stay empty.
Credential guardThe run is refused if the context file has a field name containing password, token, secret, api_key, cookie or credential.

4. Run command and options

python -m simm run --crif <CRIF file> --valuation-date <YYYY-MM-DD> --context <context file> [options]
OptionDescription
--crif file(Required) CRIF file path
--valuation-date date(Required) Valuation date. Must equal the CRIF ValuationDate.
--context file(Required) Context file path
--output result.jsonWrites the result as JSON. If the run is blocked, it writes the full list of issues instead.
--include-traceAdds the full calculation trace to --output. The file gets large.
--summary-csv summary.csvWrites the counterparty / netting set / product class / risk class table as CSV.
--version 2.7Sets the SIMM version explicitly. A warning is shown if it differs from the scheduled one.
--netting-set-column nameUses another CRIF column (e.g. PortfolioId) as the netting set. Not allowed if the CRIF already has a NettingSet column.
--excel-serial-datesConverts Excel date numbers (e.g. 46203) to 2026-06-30 format.
--quietDoes not print the summary. Use it when you only need the files.

Options that change the input, such as --netting-set-column and --excel-serial-dates, are recorded in input_transformations in the JSON result.

Exit codes

CodeMeaning
0Calculation succeeded

5. Reading the results

5.1 How amounts add up

Portfolio totalSimple sum of the counterparty totals
└ CounterpartySimple sum of its netting set totals
└ Netting setSimple sum of its product class IMs plus add-ons. Netting sets never offset each other.
└ Product classRisk class IMs combined with correlations (square root of the sum of squares) × multiplier
└ Risk classDelta + Vega + Curvature (+ BaseCorr for qualifying credit)

6. SIMM version selection

ISDA announces each version with a "use from close of business (COB)" date. The engine uses the latest version whose date is on or before the valuation date.

VersionUse from (COB)Valuation dates it is used for
2.52022-12-022022-12-02 to 2023-07-13
2.5A2023-07-142023-07-14 to 2023-11-30
2.62023-12-012023-12-01 to 2024-12-05
2.72024-12-062024-12-06 to 2025-07-10
2.7+24122025-07-112025-07-11 to 2025-12-04
2.8+25062025-12-052025-12-05 to 2026-07-09
2.8+25122026-07-102026-07-10 onwards

To see which version applies to a date:

python -m simm versions --date 2025-03-31
{ "version": "2.7", "use_from_cob": "2024-12-06", "valuation_date": "2025-03-31",
  "beyond_verified_schedule": false, "schedule_verified_through": "2026-10-06", "warning": null }
  • Before 2022-12-02: not supported (No SIMM package scheduled error).
  • After 2026-10-06: calculated with the latest version and flagged with a warning, because ISDA may have published a newer version since. Check the ISDA website; if there is a new version, add it as described in section 8.
  • Setting the version yourself: if you agreed a different version with your counterparty, use --version. A warning is recorded on screen and in the JSON.

7. Using the engine from Python

You can call the engine from Python code instead of the command line. A fixed add-on amount can only be given this way.

import json
from simm.crif import read_crif, validate
from simm.engine import Engine
from simm.parameters import ParameterPackage
from simm.versioning import select_version

valuation_date = '2026-06-30'
context = json.load(open('examples/context.json', encoding='utf-8'))
context['valuation_date'] = valuation_date

selection = select_version(valuation_date)            # select the version
package = ParameterPackage(selection['version'])      # load parameters (hash checked)
headers, rows = read_crif('examples/crif_example.csv')
validation = validate(headers, rows, package, context)

if validation.blocked:
    for issue in validation.issues:
        print(issue.severity, issue.code, issue.row_id, issue.message)
else:
    config = {'fixed_addons': [{
        'scope': {'counterparty': 'CP_B', 'legal_entity': 'ENTITY_1', 'netting_set': 'NS_B2',
                  'csa': 'CSA_1', 'direction': 'collect', 'regulation': 'EXAMPLE_REGULATION'},
        'amount_usd': '10000',
        'source': 'CSA side letter 2026-01-15'}]}
    result = Engine(package).calculate(validation, config)
    print(result['simm_version'], result['total_simm'])
  • scope: all six fields must match a scope in the JSON result. If no netting set matches, an error is raised.
  • amount_usd: a USD amount of 0 or more. Pass it as a string to keep full precision. source (the agreement reference) must not be empty.
  • Running this example raises NS_B2 from 488,000 to 498,000 and the total to 33,506,812.42.

8. Adding a new SIMM version

When ISDA publishes a new version and the formulas (methodology sections B-C) are unchanged, adding its parameters is enough.

1
Create the folder

Create parameters\simm_<version>, replacing . and + with _ (e.g. 2.8+2512 → simm_2_8_2512).

2
Write parameters.json

Copy the file of an existing version and change the values according to the new ISDA methodology document. Update version and sources as well.

3
Compute the hash

Put the file's SHA-256 into sha256 of manifest.json, in lower case.

(Get-FileHash parameters\simm_X_Y\parameters.json).Hash.ToLower()    # Windows PowerShell
shasum -a 256 parameters/simm_X_Y/parameters.json                  # macOS / Linux
4
Add it to the schedule

Append version, use_from_cob, announcement and methodology_pdf to versions in parameters\version_schedule.json, and set verified_through to the date you checked ISDA's announcements.

5
Check

Run the tests and check that python -m simm versions lists the new version.

When parameters are not enoughIf the formulas change or a new methodology_id appears, the engine code must change too (for example SUPPORTED_METHODOLOGIES in src\simm\parameters.py). Parameter files are checked when loaded: hash, symmetry and range of correlation matrices, and concentration thresholds.

10. FAQ

Q. I need results in another currency, such as KRW.

The engine reports USD only. Multiply the result by the FX rate you need. Which rate (date, source) to use should follow your agreement with the counterparty.

Q. Can two CSAs with the same counterparty be calculated together?

Each CSA (netting set) is calculated separately and the results are added. To offset them, give rows of both CSAs the same NettingSet value, but only if the legal agreements actually allow it.

Q. My CRIF contains trades under Schedule IM.

Rows whose IMModel is not SIMM block the run. Move Schedule rows to a separate file.

Q. I only get warnings (WARNING). Is that OK?

Yes, the calculation runs. LATEST_RDS_UNVERIFIED always appears. NETTED_ROWS means several rows of the same risk factor were added together; check that this is intended.

Q. My result differs slightly from my counterparty's or another system's.

Check, in this order: ① the same SIMM version ② the same CRIF (crif_sha256) ③ the same netting sets ④ the same FX rates for non-USD rows ⑤ the same rounding. Comparing intermediate values with --include-trace helps find where the difference starts.
