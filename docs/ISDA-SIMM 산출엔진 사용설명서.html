무엇을 하는 프로그램인가요?

  • 파생상품 거래의 민감도 파일(CRIF)을 넣으면, ISDA SIMM 방법으로 개시증거금(IM)을 계산해 USD로 보여줍니다.
  • 계산 전에 입력 파일이 규칙에 맞는지 꼼꼼히 검사합니다. 문제가 있으면 계산하지 않고 무엇이, 몇 번째 줄에서 틀렸는지 알려줍니다.
  • 평가일에 맞는 SIMM 버전(2.5 ~ 2.8+2512)을 자동으로 골라 씁니다.

요약 2처음 실행해 보기예시 데이터로 10분이면 됩니다 · Windows 기준
1
Python이 설치되어 있는지 확인

시작 메뉴에서 터미널(또는 PowerShell)을 열고 입력합니다.

python --version

Python 3.11.x 이상이 나오면 다음 단계로 갑니다.

오류가 나거나 Microsoft Store가 열리면Python이 없는 것입니다. python.org에서 내려받아 설치하세요. 설치 화면에 "Add python.exe to PATH" 항목이 있으면 꼭 체크하고, 설치 후 터미널을 새로 여세요.
2
산출엔진 내려받기
  1. 브라우저에서 github.com/moulinnoirai-cell/ISDA-SIMM-Calculator 에 들어갑니다.
  2. 초록색 [Code] 버튼 → [Download ZIP]을 누릅니다.
  3. 원하는 곳(예: C:\SIMM)에 압축을 풉니다. ISDA-SIMM-Calculator-main 폴더가 생깁니다.
3
산출엔진 폴더에서 터미널 열기

ISDA-SIMM-Calculator-main 폴더를 열고, 빈 곳에서 마우스 오른쪽 클릭 → [터미널에서 열기]를 누릅니다. src, examples, crif 폴더가 보이는 위치여야 합니다.

4
준비 명령 입력 (터미널을 새로 열 때마다 첫 줄을 한 번 입력) 
$env:PYTHONPATH = "src"
python -m simm versions

아래처럼 버전 목록이 나오면 준비 완료입니다.

2.5       use from COB 2022-12-02  https://www.isda.org/...
...
2.8+2512  use from COB 2026-07-10  https://www.isda.org/...
5
예시 계산 실행 
python -m simm run `
  --crif examples\crif_example.csv `
  --valuation-date 2026-06-30 `
  --context examples\context.json

화면에 아래 줄이 보이면 성공입니다.

SIMM 2.8+2506 | valuation 2026-06-30 | USD | SHADOW
Portfolio total: 33,496,812.42 USD
명령 입력 요령줄 끝의 `(백틱)은 "다음 줄에 이어짐"이라는 뜻입니다. 여러 줄을 한꺼번에 복사해 붙여넣거나, 백틱 없이 한 줄로 이어 써도 됩니다.

평가일이 2026-06-30인데 2.8+2506이 선택된 것은 2.8+2512가 2026-07-10부터 적용되기 때문입니다(상세편 6장).

요약 3내 데이터로 계산하기파일 2개를 준비해 명령 1번 실행
A
CRIF 파일 만들기
  1. crif\crif_template.csv를 산출엔진 폴더에 복사하고 이름을 my_crif.csv로 바꿉니다.
  2. 엑셀로 열어 첫 줄(열 이름)은 그대로 두고 둘째 줄부터 데이터를 채웁니다. 작성 규칙은 요약 4에 있습니다.
  3. [다른 이름으로 저장] → "CSV UTF-8(쉼표로 분리)" 형식으로 저장합니다.
작성 예시가 필요하면examples\crif_example.csv를 여세요. 금리, FX, 신용, 주식, 상품, Add-on까지 모든 종류의 작성 예가 들어 있습니다.
B
설정 파일 만들기

config\context.template.json을 산출엔진 폴더에 복사해 my_context.json으로 바꾸고, 메모장으로 열어 아래 항목을 채웁니다.

항목넣을 값예
directioncollect(받을 증거금) 또는 post(줄 증거금) 중 하나"collect"
regulation규제 이름. 비워 두면 안 됩니다."REG_A"
legal_entity우리 쪽 법인 이름"MY_ENTITY"
csaCSA(담보계약) 이름"CSA_1"
currency_codesCRIF에 나오는 모든 통화. 기본 목록에 없는 통화만 추가"USD", "EUR", ...
source
(unit_declarations 안)		CRIF에 쓴 Risk Type마다 "이 단위로 산출했다"는 근거. 쓰지 않는 Risk Type은 비워 둬도 됩니다."리스크 시스템 산출 사양서 4.1절"
 
"direction": "collect",
"regulation": "REG_A",
"Risk_IRCurve": { "unit": "PV01_PER_1BP", "source": "리스크 시스템 산출 사양서 4.1절" },
주의unit 값은 바꾸지 마세요. 사용하는 Risk Type의 source가 비어 있으면 계산이 차단됩니다. 단위가 틀리면 결과가 크게 틀어지기 때문에 일부러 이렇게 만들었습니다.
C
실행 (터미널을 새로 열었다면 $env:PYTHONPATH = "src" 먼저) 
python -m simm run `
  --crif my_crif.csv `
  --valuation-date 2026-06-30 `
  --context my_context.json `
  --output result.json `
  --summary-csv summary.csv

화면에 요약이 나오고, 산출엔진 폴더에 result.json(전체 결과)과 summary.csv(엑셀로 볼 수 있는 표)가 만들어집니다. 평가일(2026-06-30)은 내 CRIF의 ValuationDate와 같게 바꿔 입력하세요.

요약 4작성 규칙과 막혔을 때자주 틀리는 것만 모았습니다

CRIF 작성 6가지 규칙

1
날짜는 2026-06-30 형식. 실행할 때 입력한 평가일과 같아야 합니다.
2
숫자에 쉼표를 쓰지 않습니다. 1000 (O), 1,000 (X)
3
셀 앞뒤에 공백이 있으면 안 됩니다.
4
계산에는 AmountUSD만 쓰입니다. USD 행은 Amount와 AmountUSD가 같아야 합니다.
5
테너는 소문자 표준값만: 2w 1m 3m 6m 1y 2y 3y 5y 10y 15y 20y 30y (신용은 1y 2y 3y 5y 10y)
6
Risk Type마다 비워야 하는 칸이 있습니다. 아래 예와 상세편 2장을 보세요.

자주 쓰는 Risk Type 작성 예

ProductClassRiskTypeQualifierBucketLabel1Label2AmountAmountCurrencyAmountUSD
RatesFXRisk_IRCurveUSD15yOIS25000USD25000
RatesFXRisk_FXEUR900000USD900000
RatesFXRisk_FXVolEURUSD1y30000USD30000
EquityRisk_EquityISIN:KR00000000361200000USD200000
CreditRisk_CreditQ *ISIN:XS000000001635y15000USD15000
빈칸은 비워 둡니다. 앞쪽 5개 열(ValuationDate ~ IMModel)은 생략했습니다. * 신용 행은 PaymentCurrency(지급통화)도 넣습니다.

산출엔진은 src 폴더의 코드를 씁니다. 터미널을 열 때마다 Python에 그 위치를 알려 줘야 합니다.

터미널준비 명령여러 줄 명령의 줄 잇기 문자
Windows PowerShell / 터미널$env:PYTHONPATH = "src"줄 끝에 ` (백틱)

macOS·Linux에서는 경로 구분자를 /로 씁니다(예: examples/crif_example.csv). 일부 환경에서는 python 대신 python3을 씁니다.

1.5 설치해서 쓰기 (선택)

산출엔진 폴더에서 pip install -e .을 실행하면 준비 명령 없이 어디서나 simm 명령을 쓸 수 있습니다.

  • -e를 꼭 붙이세요. 산출엔진은 내려받은 폴더의 parameters를 직접 읽기 때문에, 일반 설치(pip install .)로는 동작하지 않습니다.
  • 설치 중에 인터넷에서 빌드 도구를 받습니다. 사내망 등에서 실패하면 1.4의 설치 없는 방법을 쓰세요.

2. CRIF 파일 작성

CRIF(Common Risk Interchange Format)는 SIMM 계산용 민감도를 주고받는 표준 형식입니다. 한 줄이 위험요인 하나의 민감도입니다. 산출엔진은 CSV, TSV, 시트가 하나인 XLSX 파일을 읽습니다.

2.1 열 설명

열필수설명예
ValuationDate권장평가일(YYYY-MM-DD). 실행할 때 준 평가일과 같아야 합니다.2026-06-30
Counterparty예 *거래상대방 식별자CP_A
NettingSet예 *Netting Set(CSA 포트폴리오). Netting Set끼리는 상계하지 않고 단순 합산합니다.NS_A1
TradeID선택거래 번호. 다른 거래의 같은 내용 행을 구분해 줍니다.T001
IMModel선택SIMM만 허용합니다. Schedule 등은 실행이 차단됩니다.SIMM
ProductClass예RatesFX, Credit, Equity, Commodity 중 하나RatesFX
RiskType예2.2의 표 참고Risk_IRCurve
Qualifier예통화, 발행자, 지수 등USD
Bucket예(빈칸 가능)Risk Type별 버킷1
Label1예(빈칸 가능)테너 또는 옵션 만기5y
Label2예(빈칸 가능)금리 커브 종류 등OIS
Amount예AmountCurrency 기준 민감도25000
AmountCurrency예Amount의 통화(ISO 코드)USD
AmountUSD예USD 기준 민감도. 계산에는 이 값만 씁니다.25000

  • 저장 형식: "CSV UTF-8(쉼표로 분리)"로 저장합니다. 다른 CSV 형식은 한글이 깨지거나 읽히지 않을 수 있습니다.

2.5 통화가 USD가 아닌 행

  • AmountCurrency가 EUR 등이어도 됩니다. 이때 AmountUSD에는 CRIF를 만든 쪽에서 미리 환산한 USD 값을 넣어야 합니다. 산출엔진은 환율을 검사하지 않고 FX_RATE_UNVERIFIED 경고만 남깁니다.
  • Amount와 AmountUSD의 부호가 다르거나 한쪽만 0이면 오류입니다.

7. Python 코드에서 직접 쓰기

명령 대신 Python 코드에서 부를 수도 있습니다. 고정 금액 Add-on은 이 방법으로만 넣을 수 있습니다.

import json
from simm.crif import read_crif, validate
from simm.engine import Engine
from simm.parameters import ParameterPackage
from simm.versioning import select_version

valuation_date = '2026-06-30'
context = json.load(open('examples/context.json', encoding='utf-8'))
context['valuation_date'] = valuation_date

selection = select_version(valuation_date)            # 버전 자동 선택
package = ParameterPackage(selection['version'])      # Parameter 읽기(해시 검사 포함)
headers, rows = read_crif('examples/crif_example.csv')
validation = validate(headers, rows, package, context)

if validation.blocked:
    for issue in validation.issues:
        print(issue.severity, issue.code, issue.row_id, issue.message)
else:
    config = {'fixed_addons': [{
        'scope': {'counterparty': 'CP_B', 'legal_entity': 'ENTITY_1', 'netting_set': 'NS_B2',
                  'csa': 'CSA_1', 'direction': 'collect', 'regulation': 'EXAMPLE_REGULATION'},
        'amount_usd': '10000',
        'source': 'CSA 부속합의서 2026-01-15'}]}
    result = Engine(package).calculate(validation, config)
    print(result['simm_version'], result['total_simm'])
  • scope: 결과 JSON의 scope와 6개 항목이 모두 같아야 합니다. 맞는 Netting Set이 없으면 오류가 납니다.
  • amount_usd: 0 이상의 USD 금액. 문자열로 넣으면 정밀도가 유지됩니다. source(근거)는 비우면 오류가 납니다.
  • 위 예시를 실행하면 NS_B2가 488,000 → 498,000이 되고, 전체 합계는 33,506,812.42가 됩니다.

8. 새 SIMM 버전 추가하기

ISDA가 새 버전을 발표했을 때, 수식(방법론 B~C절)이 그대로라면 Parameter만 추가하면 됩니다.

1
폴더 만들기

parameters\simm_<버전> 폴더를 만듭니다. 버전의 .과 +는 _로 바꿉니다(예: 2.8+2512 → simm_2_8_2512).

2
parameters.json 작성

기존 버전 파일을 복사한 뒤, 새 ISDA 방법론 문서를 보고 값을 바꿉니다. version과 sources도 새 버전으로 바꿉니다.

3
해시 계산

파일의 SHA-256을 계산해 manifest.json의 sha256에 소문자로 넣습니다.

(Get-FileHash parameters\simm_X_Y\parameters.json).Hash.ToLower()    # Windows PowerShell
shasum -a 256 parameters/simm_X_Y/parameters.json                  # macOS / Linux
4
일정표 추가

parameters\version_schedule.json의 versions 끝에 version, use_from_cob, announcement, methodology_pdf를 추가하고, verified_through를 ISDA 공지를 확인한 날짜로 바꿉니다.

5
확인

테스트를 돌리고 python -m simm versions로 새 버전이 보이는지 확인합니다.

Parameter만으로 안 되는 경우새 버전에서 수식 자체가 바뀌었거나 새 methodology_id가 생겼다면 엔진 코드(src\simm\parameters.py의 SUPPORTED_METHODOLOGIES 등)도 고쳐야 합니다. Parameter 파일은 읽을 때 해시, 상관계수 행렬의 대칭·범위, 집중도 기준값을 자동으로 검사합니다.

9. 주의사항과 한계

  • ISDA 권리: ISDA SIMM®은 ISDA의 등록상표이자 지적재산이며 미국 특허(10,515,410) 대상입니다. parameters의 값은 ISDA 공개 문서를 옮겨 적은 것으로, 이 프로젝트의 Apache-2.0 라이선스 대상이 아닙니다.
  • ISDA 라이선스: 증거금 계산에 SIMM을 쓰려면 ISDA 라이선스가 필요할 수 있습니다. ISDA SIMM 라이선스 FAQ(isda.org)를 참고하세요.
  • 검증 수준: Parameter는 독립적으로 옮겨 적은 값과 대조했고, 수식은 별도로 구현한 계산 코드와 가상 포트폴리오로 대조했습니다. ISDA 공식 단위 테스트(유료 자료)는 실행하지 않았습니다. 자세한 내용은 docs\METHODOLOGY_NOTES.md에 있습니다.
  • CRIF 기준: 공개된 Risk Data Standards 1.36 기준입니다. PaymentCurrency·GroupName 열과 고정 Add-on 설정은 이 산출엔진의 확장이므로, 쓰는 CRIF 생산 시스템과 맞는지 확인하세요.
  • 다루지 않는 것: 환율 환산, Threshold·최소이전금액(MTA)·담보 평가, 규제 적용 범위 판단.
  • 라이선스: 코드·문서·양식은 Apache-2.0입니다. 허락 없이 사용·수정·재배포·상업적 이용이 가능하며, LICENSE와 NOTICE를 유지하고 수정한 파일에 수정 사실을 표시하면 됩니다.

10. 자주 묻는 질문

Q. KRW 등 다른 통화 결과가 필요합니다.

산출엔진은 USD 결과만 냅니다. 결과에 원하는 기준 환율을 곱해 환산하세요. 어떤 환율(기준일, 고시 기관)을 쓸지는 상대방과의 합의를 따르세요.

Q. 같은 거래상대방의 CSA 두 개를 합쳐 계산할 수 있나요?

각 CSA(Netting Set)를 따로 계산해 단순 합산합니다. 서로 상계하려면 두 CSA 행의 NettingSet을 같은 값으로 넣어야 하는데, 실제 계약 구조가 그럴 때만 하세요.

Q. CRIF에 Schedule IM 대상 거래가 섞여 있습니다.

IMModel이 SIMM이 아닌 행이 있으면 실행이 차단됩니다. Schedule 행은 별도 파일로 분리하세요.

Q. 경고(WARNING)만 있는데 괜찮나요?

계산은 정상 진행됩니다. LATEST_RDS_UNVERIFIED는 항상 나오는 안내입니다. NETTED_ROWS는 같은 위험요인의 여러 행을 합쳤다는 뜻이니 의도한 것인지 확인하세요.

Q. 상대방이나 외부 시스템 결과와 조금 다릅니다.

① 같은 SIMM 버전인지 ② 같은 CRIF(crif_sha256)인지 ③ Netting Set 구분이 같은지 ④ 비USD 행의 환산 환율이 같은지 ⑤ 반올림 방식이 같은지 순서로 확인하세요. --include-trace로 중간값을 비교하면 차이가 생긴 곳을 찾기 쉽습니다.
